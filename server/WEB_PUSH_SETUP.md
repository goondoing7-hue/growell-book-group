# GROWELL 웹 푸시 설정

## 2026-10-26 오후 11시 습관 체크

`web-push-habits.sql`은 모임 알림 확장 다음에 적용한다. 먼저 `habit`을 처리하는 API와 서비스 워커 배포를 확인한다. 기존 매분 DB 예약과 HTTP 워커를 그대로 사용하며 새 비밀값이나 예약 작업은 필요 없다. 적용 자체는 알림 작업을 만들지 않고 회원·습관·체크 이력을 변경하지 않는다. 기존 나눔·말씀 ON/OFF는 보존하고, 별도 `habit_check` 선택을 추가한다. 프로필 → 설정 → 알림에는 **오후 11시 습관 체크** ON/OFF만 표시한다. 구버전 클라이언트가 해당 선택을 생략하면 저장된 선택을 유지한다. 같은 소유자의 재연결·만료 구독 교체에서도 OFF를 보관한다.

한국 시간 23:00 이상 23:15 미만에, 홈의 오늘의 습관과 같은 책 접근권한·시작일·종료일·요일 조건을 만족하면서 당일 체크가 하나라도 빠진 승인 회원의 활성 기기마다 하루 한 건을 만든다. 오늘 습관이 없거나 모두 체크했으면 만들지 않는다. 생성된 작업도 claim·snapshot·prepare에서 현재 체크·기간·요일·책 접근·계정 승인·기기 소유/세대와 알림 ON/OFF를 다시 확인한다. 전송 전에 모두 체크하면 취소한다. 알림 클릭은 오늘의 습관이 있는 홈을 열고 다른 글쓰기 화면을 대체하지 않는다. 큐와 메시지에 습관 이름·목표·원문·체크 이력을 복사하지 않는다.

같은 구독·날짜는 영구 unique 키로 중복을 막는다. 재시도는 기존 lease/prepare/uncertain 정책을 따른다. 제공사 수락이 불확실하면 자동 재전송하지 않는다. 23:30에 만료하며 다음 날 밀린 체크 알림을 보내지 않는다. 새 endpoint는 브라우저가 발급한 별도의 기기 구독으로 취급한다. 기기가 여러 개면 기기별 한 번씩 받을 수 있다. 실제 기기 표시 시각은 인터넷·절전·집중 모드 영향을 받는다.

검증은 `tests/web-push-habits-sql.test.cjs`의 합성 PostgreSQL 시계와 원본 보존/오늘 조건/시간 경계/취소/권한 테스트, 서버·서비스 워커 연결 테스트를 사용한다. 운영 적용 전후에는 `web-push-habits-verification.sql`의 읽기 전용 집계와 원문 fingerprint를 비교한다. 실제 회원 체크나 습관을 테스트용으로 수정하거나 23시 tick을 임의 호출하지 않는다. 적용 후 익명·회원에게 새 함수 실행권이 없는지 및 기존 두 Cron이 유지되는지 확인한다.

## 2026-10-24 모임 기록 최초 공개 알림

모임 기록은 `draft` 동안 알림이 없다. 관리자가 처음 `published`로 공개할 때만 같은 책을 읽을 수 있는 승인 회원의 `new_posts` ON 기기에 회차가 표시된 알림을 만든다. 작성자 본인, 단순 수정, 과거 기록, 같은 기기의 재게시 알림은 제외한다. 알림에는 책 ID·기록 ID·회차만 사용하며 제목·본문·질문·개인 통찰을 복사하지 않는다. 알림을 누르면 해당 회차의 모임 기록을 열고, 다른 페이지에서 작성 중인 글은 유지한다.

설치 순서는 `web-push.sql` → `web-push-materials.sql` → `web-push-meetings.sql`이다. 모임 SQL은 항상 마지막이어야 한다. 먼저 `meeting`을 처리하는 서버와 서비스 워커 배포의 Ready를 확인한 뒤 모임 SQL을 적용한다. 신규 컬럼·작업 종류·최초 공개 트리거만 추가하며 기존 글·구독·ON/OFF·이미 대기 중인 작업을 다시 만들거나 초기화하지 않는다. 발송 직전에도 게시 상태·작성자/수신자 승인·책 접근권한·기기 소유/세대·동일 회차/책을 재검증한다. SQL 적용 자체는 과거 기록을 알림 큐에 넣지 않는다. 검증은 `web-push-meetings-verification.sql`의 읽기 전용 집계와 합성 PostgreSQL 테스트로 수행한다.

이 기능은 회원이 기기에서 알림을 직접 허용한 뒤 작동한다. Google·Microsoft 연결 권한과 별개이며, 계정을 연결했다고 브라우저의 알림 권한을 대신 허용하지 않는다.

로그인·세션 복원에서 인증과 가입 승인을 확인한 회원에게 미연결 기기의 알림 안내를 자동 표시한다. 자동 실행은 현재 기기의 설정 조회만 수행하며, 실제 권한 요청과 구독은 **알림 받기** 클릭에서만 시작한다. 연결된 기기·알림 차단·미지원 환경에는 일반 연결 안내를 반복하지 않는다. iOS 홈 화면 미설치 환경은 설치 방법만 안내한다. **나중에**·닫기·뒤로가기는 회원 키를 해시한 브라우저 설정에 시각만 저장하여 7일간 보류한다. 원문·토큰·기기 구독을 여기에 저장하지 않는다. 글쓰기·다른 팝업·입력·저장 중에는 표시를 미룬다. 로그아웃과 계정 변경 시 대기 요청과 안내를 정리하며, 연결 성공 자체를 영구 거절로 저장하지 않는다.

## 기존 기록 보존

- `web-push.sql`은 구독·작업 테이블, 서비스 전용 함수와 `posts`·`material_notes`의 **INSERT 후** 트리거를 구성한다. 이미 운영 중인 설치에는 `web-push-materials.sql`로 자료실 트리거와 선택적인 자료 ID 항목만 추가한다.
- 기존 회원·나눔·개인 기록·통찰·습관·자료·모임 기록의 본문, ID, 작성 시각, 이력을 수정하거나 삭제하지 않는다.
- 설치·재설치·알림 연결 시 과거 글을 일괄 발송하지 않는다. 게시글 수정도 새 알림을 만들지 않는다.
- 기기 연결 해제는 암호화된 기기 구독만 비활성화하며 원문을 삭제하지 않는다.
- 설치는 회원을 자동 등록하지 않는다. 각 기기의 명시적인 알림 허용과 연결이 필요하다.

## 서버 환경변수

기존 운영 프로젝트 `growell_book_group`의 Production 환경만 사용한다. 비밀값은 채팅, 로그, 저장소, 브라우저 번들에 출력하지 않는다.

| 이름 | 용도 |
| --- | --- |
| `GROWELL_WEB_PUSH_PUBLIC_KEY` | VAPID 공개 키. 연결된 브라우저가 구독을 만들 때 받는다. |
| `GROWELL_WEB_PUSH_PRIVATE_KEY` | 대응하는 VAPID 비밀 키. 서버에서만 사용한다. |
| `GROWELL_SYNC_KEY` | 기존 32바이트 Base64 암호화 키. 전체 기기 구독을 저장하기 전에 암호화한다. |
| `SUPABASE_SERVICE_ROLE_KEY` | 기존 서버 전용 DB 권한. 회원 요청은 별도로 JWT와 승인 상태를 검증한다. |
| `GROWELL_SUPABASE_URL` | 기존 Supabase 주소. 기본값은 기존 운영 프로젝트이다. |
| `GROWELL_SYNC_ORIGIN` | 기존 운영 원본 `https://growell-book.vercel.app`. |
| `CRON_SECRET` | 선택적인 Vercel Cron 인증. Supabase 예약 실행에는 필요하지 않다. |

VAPID 키 쌍은 P-256으로 한 번 생성하고 안전하게 보관한다. 새로 고침이나 배포 때마다 다시 만들지 않는다. 비밀 키나 암호화 키를 바꾸면 기존 구독이 작동하지 않을 수 있으므로 회원이 기기 알림을 다시 연결할 수 있도록 안내한다. 브라우저에 필요한 공개 키만 반환한다.

## 적용 순서

1. 합성 데이터로 `node --test tests/web-push-sql.test.cjs` 및 웹 푸시 서버·기기 테스트를 통과시킨다.
2. 기존 운영 Supabase에 `server/web-push.sql`을 적용한다. 원본 테이블 백필, 초기화, 데이터 덮어쓰기는 수행하지 않는다.
3. 위 서버 환경변수를 확인하고 웹 푸시 API·서비스 워커가 포함된 버전을 기존 운영 주소로 배포한다.
4. 기존 Vault에 `growell_habit_sync_worker_secret`이 유효한 32~256자 값으로 **정확히 하나** 있는지 확인한다. 값 자체를 조회 결과나 로그에 출력하지 않는다. 이미 다른 작업에서 쓰는 값을 임의로 교체하지 않는다.
5. `server/web-push-schedule.sql`을 적용한다. `growell-daily-verse-queue`가 DB 안에서 오전 말씀 작업을 먼저 보관하고, 별도 `growell-web-push` 예약 작업이 1분마다 고정된 `/api/web-push?action=worker`에 요청한다. 두 작업은 독립적으로 실행되며 같은 이름으로 다시 적용하면 중복 예약을 만들지 않는다.
6. 회원 본인이 알림을 받을 기기에서 **프로필 → 연동 → 푸시 알림**을 열고 연결한다. 테스트 알림은 테스트 버튼으로만 확인한다. 실제 글을 테스트 목적으로 게시하거나 수정하지 않는다.

### 자료실 알림 확장

기존 푸시 설치에는 자료실 확장 SQL만 추가한다. 먼저 `material` 작업을 처리하는 서버와 서비스 워커를 배포해 **Ready**를 확인한 다음 `server/web-push-materials.sql`을 적용한다. 구버전 서버에 새 종류의 작업이 전달되는 순서를 피한다. 기존 `new_posts` 선택을 나눔·자료 공통 설정으로 유지하며 OFF 상태와 기기 연결 정보를 변경하지 않는다. 회원의 재연결이나 과거 자료의 재저장은 필요하지 않다. 마이그레이션은 자료·게시글 원본을 읽는 것 외에 수정하지 않고, 과거 자료 알림을 만들지 않는다.

적용 후 트리거·자료 ID 열과 기존 예약 작업의 존재를 메타데이터로 확인한다. 신규 자료 발행 테스트는 합성 데이터가 든 임시 DB에서만 수행한다. 실제 회원 자료를 테스트 목적으로 게시·수정하지 않는다.

2026-10-19 운영 적용: `0a280c9`의 서버·서비스 워커 배포가 Ready인 것을 확인한 뒤 사용자의 명시적 승인으로 자료실 확장 SQL을 적용했다. 자료 ID 열·작업 종류·신규 INSERT 트리거, 익명·회원 역할의 직접 함수 실행 차단을 확인했다. 적용 전후 회원·나눔·자료·개인 기록·습관의 행 수와 기존 발송 작업 집계·두 예약 작업은 같았으며, 과거 자료 알림은 생성하지 않았다. 새 자료 발행부터 동작하며 기존 기기는 GROWELL을 다시 열어 최신 서비스 워커를 받아야 한다. 이 확인은 휴대폰의 실제 새 자료 알림 표시 확인을 대신하지 않는다.

백그라운드 수신 확인은 기존 `test` 요청에 `delaySeconds: 60`을 추가한다. 본인이 연결한 기기만 대상으로 하며, DB가 60초 뒤부터 전송할 작업을 보관한다. 브라우저를 닫거나 화면을 잠가도 브라우저 타이머 없이 다음 서버 예약 실행이 처리한다. 1분마다 실행되므로 실제 도착은 요청 후 약 1~2분일 수 있다. 기존 즉시 테스트와 같은 60초 쿨다운을 사용하고, 예정 시각부터 5분이 지나면 전송하지 않는다. 이 검사는 오전 말씀 수신 원인을 단정하지 않으며, 서버 수락과 휴대폰 표시를 구분해 확인하기 위한 기능이다.

예약 요청의 `x-growell-worker-secret`은 Vault에서 실행 시 읽는다. SQL 파일에 비밀값이나 관리자 토큰을 넣지 않는다. 서비스 RPC `growell_web_push_worker_authorized`는 일치 여부만 반환한다.

## 프로필 설정과 만료 연결 복구

프로필 메뉴의 `설정`에서 `알림`과 `연동` 탭을 구분한다. 일반 회원은 기기 연결·해제, 수신할 알림 두 종류와 테스트 한 개, Google 및 습관 알림의 필수 연결 설정을 사용한다. 로컬 표시·지연 테스트·최근 전체 발송 시각과 서비스 상세 점검은 관리자에게만 보여준다. 화면 구분은 서버 권한을 대신하지 않으며 기존 인증·본인 소유 검증은 그대로 유지한다.

같은 회원·같은 endpoint의 소유 표식과 boolean 설정을 확인한 비활성 구독은 기존 OFF 선택과 안전한 만료 사유만 반환한다. 다른 회원·없는 endpoint는 연결 정보가 없는 응답을 유지하며 device ID·구독·키·암호문은 반환하지 않는다. `다시 연결하기`를 직접 누르면 현재 루트 서비스 워커와 정확한 구독을 확인하고 오래된 native 구독을 해제한 뒤 새 구독을 발급한다. 앱 재접속·설정 조회는 구독을 자동 교체하거나 수신 설정을 켜지 않는다.

재연결 전 수신 설정의 OFF 값을 회원 해시 키의 두 boolean으로 보관하고 읽어 확인한다. 저장 실패·손상·계정 변경이면 교체를 중단한다. 새 구독 발급 후 서버 저장에 실패해도 다시 열었을 때 OFF를 유지하며, 서버의 일치 상태를 확인한 뒤 이 동작이 만든 정확한 보관값만 정리한다. 원문·토큰·endpoint·이메일은 이 임시 보관에 저장하지 않는다.

삼성 리마인더의 전체화면·긴 소리인 ‘강하게’와 Apple의 ‘긴급’ 알람은 현재 Microsoft To Do 동기화로 지정할 수 없다. 설정에는 기기별 조절 방법을 안내한다. Graph 작업의 importance와 실제 알림 소리·전체화면은 별개이며 강도가 자동 변경됐다고 표시하지 않는다.

## 알림 동작

### 새로운 나눔

공개 글이 새로 INSERT될 때만 구독된 기기별 작업을 한 번 만든다. 본인이 작성한 글, 비공개·삭제된 글, 미승인·탈퇴한 작성자의 글은 제외한다. 승인된 활성 수신자가 현재 읽을 수 있는 책의 글만 대상이며, 잠긴 책은 기존 운영자 권한을 따른다.

기기당 작업에는 글 ID·책 ID와 발송 상태만 저장한다. 글 제목·본문·통찰 답변·개인 기록·프로필 이메일은 복사하지 않는다. 알림 본문은 “새로운 나눔이 올라왔어요”라는 일반 안내이다. 글을 누르면 앱의 기존 조회·권한 처리를 통해 해당 글로 이동한다.

승인 철회·계정 연결 해제·기기 해제·글 공개 범위 변경·책 잠금·알림 OFF를 큐 생성 당시뿐 아니라 **발송 직전**에도 다시 확인한다. 글이 다른 책으로 이동했을 경우 기존 경로의 알림을 취소한다.

### 새로운 자료

`material_notes`에 새 글이 등록될 때만 `material` 작업을 만든다. 본인이 작성한 자료와 수정, 삭제·비공개 자료, 읽을 수 없는 책은 제외한다. `new_posts`를 켠 기기에만 보내므로 화면에서는 **새 나눔·자료 알림**으로 표시한다. 회원·작성자 승인, 기기 세대, 글의 책과 접근 가능 여부는 발송 직전에도 다시 확인한다.

자료 작업은 자료 ID·책 ID만 담고 제목·본문·작성자 정보는 복사하지 않는다. 알림 제목은 **GROWELL 새 자료**, 본문은 고정된 모임 책 이름과 새 자료 안내이다. 알림을 누르면 해당 책의 기존 자료 상세 화면으로 이동하며, 작성 중인 다른 화면을 강제로 이동시키지 않는다.

### 매일 오전 9시 말씀

기준은 **한국 시간(Asia/Seoul)**이다. 매일 09:00 이상 09:15 미만의 예약 실행에서 당일 작업만 만들며 같은 기기·같은 날짜는 중복되지 않는다. 알림 내용은 홈 화면의 `dailyVerseDomain.js`·`dailyVerses.js`가 고르는 같은 날짜의 말씀이다. 회원 위치의 시간대로 다시 계산하지 않는다.

말씀 작업 생성은 DB 예약 실행으로도 수행하므로, 전송 API가 잠시 중단되거나 인증에 실패하더라도 이미 예약된 작업은 DB에 남는다. HTTP 워커의 중복 생성 확인도 그대로 유지하며 같은 날 같은 기기에 두 번 발송하지 않는다. 발송은 서버에서 진행하므로 기기에서 사이트를 열어둘 필요가 없다. API·제공사 장애가 만료 시각까지 이어지면 해당 말씀을 수신하지 못할 수 있다.

당일 작업은 한국 시간 10:00에 만료된다. 서버가 09:15 이후 복구되어도 지난 말씀을 몰아서 보내지 않으며, 어제 말씀은 유효기간이 남아 있더라도 발송하지 않는다. 인터넷 연결·절전·집중 모드에 따라 실제 기기 표시가 늦어질 수 있다. 제공사에 전달할 TTL도 남은 유효기간 안으로 제한한다.

## 기기·운영 제한

- 한 회원은 활성 기기 최대 5개를 연결할 수 있다. 각 기기에서 별도로 알림 허용이 필요하다.
- 같은 기기에서 다른 계정으로 명시적으로 연결하면 그 기기의 소유자가 바뀐다. 이전 계정은 구독 상태 조회·수정·해제·발송에 다시 접근할 수 없다. 이전 발송 작업의 세대도 무효화된다.
- 새 나눔·자료와 매일 말씀은 기기별로 각각 끌 수 있다. 동일 계정에서 다시 연결해도 기존 OFF 선택을 유지한다.
- 테스트 알림은 기기당 60초에 한 번으로 제한하며 재연결로 우회하지 못한다.
- 테스트 작업마다 별도 알림 태그를 사용한다. 새 나눔·자료와 말씀은 글·자료·날짜별 태그를 유지한다. 회원이 허용한 화면 표시용 메시지는 `Urgency: high`로 전달을 요청하며, 기기 표시 시각을 보장하지는 않는다.
- 404/410처럼 만료된 구독은 비활성화하고 원문은 유지한다.
- 일시적 제공사 실패는 제한된 재시도로 복구한다. 최대 5회 후 멈추며, 제공사 수락 여부가 불명확한 발송은 자동 재전송하지 않는다. 잠금·해제 등으로 자격을 잃으면 대기 작업을 취소 상태로 남긴다.
- iPhone·iPad는 지원되는 iOS/iPadOS의 홈 화면 웹 앱에서 실행하고 기기에서 알림을 허용해야 한다. 지원하지 않거나 권한이 차단된 기기에는 연결 안내만 표시한다.

## 안전한 확인

기존 회원 글·습관·자료를 테스트용으로 수정하지 않는다. 데이터베이스 검증은 합성 데이터가 든 임시 PGlite에서 수행한다. 운영에서는 예약 작업의 존재, 고정 오류 코드, 상태·수신 건수와 본인이 요청한 테스트 알림만 확인한다. 원시 구독·암호화 키·제공사 오류 본문·JWT·실제 회원 본문을 진단 로그에 담지 않는다.

HTTP 워커의 응답은 `queued`(이번 실행에서 생성), `claimed`(처리권 확보), `processed`(처리 진행), `accepted`(제공사 수락), `deferred`(실행 시간 예산으로 보류) 합계만 반환한다. DB 예약이 먼저 만든 경우 `queued=0`이어도 정상이다. 빈 큐와 처리 시간 부족을 구분하되, 이 합계를 기기의 실제 표시 확인으로 해석하지 않는다.

제공사 수락(`sent`, `last_sent_at`)과 기기 알림 표시를 구분한다. 연결 화면의 **최근 서버 발송**은 제공사 수락 시각이며 수신 확인이 아니다. **기기 알림 표시 확인**은 현재 연결된 동일 원점·루트 서비스 워커의 `showNotification`만 호출하며 서버 테스트 작업을 만들지 않는다. 사용자에게 두 검사 결과를 각각 확인하여, 로컬 표시/기기 설정과 서버→푸시 서비스→기기 전달 중 어느 구간인지 좁힌다. 로컬 표시 API가 성공해도 실제 배너나 소리가 났다고 단정하지 않는다.
