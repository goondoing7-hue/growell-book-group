# GROWELL 웹 푸시 설정

이 기능은 회원이 기기에서 알림을 직접 허용한 뒤 작동한다. Google·Microsoft 연결 권한과 별개이며, 계정을 연결했다고 브라우저의 알림 권한을 대신 허용하지 않는다.

로그인·세션 복원에서 인증과 가입 승인을 확인한 회원에게 미연결 기기의 알림 안내를 자동 표시한다. 자동 실행은 현재 기기의 설정 조회만 수행하며, 실제 권한 요청과 구독은 **알림 받기** 클릭에서만 시작한다. 연결된 기기·알림 차단·미지원 환경에는 일반 연결 안내를 반복하지 않는다. iOS 홈 화면 미설치 환경은 설치 방법만 안내한다. **나중에**·닫기·뒤로가기는 회원 키를 해시한 브라우저 설정에 시각만 저장하여 7일간 보류한다. 원문·토큰·기기 구독을 여기에 저장하지 않는다. 글쓰기·다른 팝업·입력·저장 중에는 표시를 미룬다. 로그아웃과 계정 변경 시 대기 요청과 안내를 정리하며, 연결 성공 자체를 영구 거절로 저장하지 않는다.

## 기존 기록 보존

- `web-push.sql`은 새 구독·작업 테이블, 서비스 전용 함수와 `posts`의 **INSERT 후** 트리거만 추가한다.
- 기존 회원·나눔·개인 기록·통찰·습관·자료·모임 기록의 본문, ID, 작성 시각, 이력을 수정하거나 삭제하지 않는다.
- 설치·재설치·알림 연결 시 과거 글을 일괄 발송하지 않는다. 게시글 수정도 새 알림을 만들지 않는다.
- 기기 연결 해제는 암호화된 기기 구독만 비활성화하며 원문을 삭제하지 않는다.
- 설치는 회원을 자동 등록하지 않는다. 각 기기의 명시적인 알림 허용과 연결이 필요하다.

## 서버 환경변수

기존 운영 프로젝트 `growell_book_group`의 Production 환경만 사용한다. 비밀값은 채팅, 로그, 저장소, 브라우저 번들에 출력하지 않는다.

| 이름 | 용도 |
| --- | --- |
| `GROWELL_WEB_PUSH_PUBLIC_KEY` | VAPID 공개 키. 연결된 브라우저가 구독을 만들 때 받는다. |
| `GROWELL_WEB_PUSH_PRIVATE_KEY` | 대응하는 VAPID 비밀 키. 서버에서만 사용한다. |
| `GROWELL_SYNC_KEY` | 기존 32바이트 Base64 암호화 키. 전체 기기 구독을 저장하기 전에 암호화한다. |
| `SUPABASE_SERVICE_ROLE_KEY` | 기존 서버 전용 DB 권한. 회원 요청은 별도로 JWT와 승인 상태를 검증한다. |
| `GROWELL_SUPABASE_URL` | 기존 Supabase 주소. 기본값은 기존 운영 프로젝트이다. |
| `GROWELL_SYNC_ORIGIN` | 기존 운영 원본 `https://growell-book.vercel.app`. |
| `CRON_SECRET` | 선택적인 Vercel Cron 인증. Supabase 예약 실행에는 필요하지 않다. |

VAPID 키 쌍은 P-256으로 한 번 생성하고 안전하게 보관한다. 새로 고침이나 배포 때마다 다시 만들지 않는다. 비밀 키나 암호화 키를 바꾸면 기존 구독이 작동하지 않을 수 있으므로 회원이 기기 알림을 다시 연결할 수 있도록 안내한다. 브라우저에 필요한 공개 키만 반환한다.

## 적용 순서

1. 합성 데이터로 `node --test tests/web-push-sql.test.cjs` 및 웹 푸시 서버·기기 테스트를 통과시킨다.
2. 기존 운영 Supabase에 `server/web-push.sql`을 적용한다. 원본 테이블 백필, 초기화, 데이터 덮어쓰기는 수행하지 않는다.
3. 위 서버 환경변수를 확인하고 웹 푸시 API·서비스 워커가 포함된 버전을 기존 운영 주소로 배포한다.
4. 기존 Vault에 `growell_habit_sync_worker_secret`이 유효한 32~256자 값으로 **정확히 하나** 있는지 확인한다. 값 자체를 조회 결과나 로그에 출력하지 않는다. 이미 다른 작업에서 쓰는 값을 임의로 교체하지 않는다.
5. `server/web-push-schedule.sql`을 적용한다. `growell-web-push` 예약 작업이 1분마다 고정된 `/api/web-push?action=worker`에 요청한다. 같은 이름으로 다시 적용하면 중복 예약을 만들지 않는다.
6. 회원 본인이 알림을 받을 기기에서 **프로필 → 연동 → 푸시 알림**을 열고 연결한다. 테스트 알림은 테스트 버튼으로만 확인한다. 실제 글을 테스트 목적으로 게시하거나 수정하지 않는다.

예약 요청의 `x-growell-worker-secret`은 Vault에서 실행 시 읽는다. SQL 파일에 비밀값이나 관리자 토큰을 넣지 않는다. 서비스 RPC `growell_web_push_worker_authorized`는 일치 여부만 반환한다.

## 알림 동작

### 새로운 나눔

공개 글이 새로 INSERT될 때만 구독된 기기별 작업을 한 번 만든다. 본인이 작성한 글, 비공개·삭제된 글, 미승인·탈퇴한 작성자의 글은 제외한다. 승인된 활성 수신자가 현재 읽을 수 있는 책의 글만 대상이며, 잠긴 책은 기존 운영자 권한을 따른다.

기기당 작업에는 글 ID·책 ID와 발송 상태만 저장한다. 글 제목·본문·통찰 답변·개인 기록·프로필 이메일은 복사하지 않는다. 알림 본문은 “새로운 나눔이 올라왔어요”라는 일반 안내이다. 글을 누르면 앱의 기존 조회·권한 처리를 통해 해당 글로 이동한다.

승인 철회·계정 연결 해제·기기 해제·글 공개 범위 변경·책 잠금·알림 OFF를 큐 생성 당시뿐 아니라 **발송 직전**에도 다시 확인한다. 글이 다른 책으로 이동했을 경우 기존 경로의 알림을 취소한다.

### 매일 오전 9시 말씀

기준은 **한국 시간(Asia/Seoul)**이다. 매일 09:00 이상 09:15 미만의 예약 실행에서 당일 작업만 만들며 같은 기기·같은 날짜는 중복되지 않는다. 알림 내용은 홈 화면의 `dailyVerseDomain.js`·`dailyVerses.js`가 고르는 같은 날짜의 말씀이다. 회원 위치의 시간대로 다시 계산하지 않는다.

당일 작업은 한국 시간 10:00에 만료된다. 서버가 09:15 이후 복구되어도 지난 말씀을 몰아서 보내지 않으며, 어제 말씀은 유효기간이 남아 있더라도 발송하지 않는다. 인터넷 연결·절전·집중 모드에 따라 실제 기기 표시가 늦어질 수 있다. 제공사에 전달할 TTL도 남은 유효기간 안으로 제한한다.

## 기기·운영 제한

- 한 회원은 활성 기기 최대 5개를 연결할 수 있다. 각 기기에서 별도로 알림 허용이 필요하다.
- 같은 기기에서 다른 계정으로 명시적으로 연결하면 그 기기의 소유자가 바뀐다. 이전 계정은 구독 상태 조회·수정·해제·발송에 다시 접근할 수 없다. 이전 발송 작업의 세대도 무효화된다.
- 새 나눔과 매일 말씀은 기기별로 각각 끌 수 있다. 동일 계정에서 다시 연결해도 기존 OFF 선택을 유지한다.
- 테스트 알림은 기기당 60초에 한 번으로 제한하며 재연결로 우회하지 못한다.
- 테스트 작업마다 별도 알림 태그를 사용한다. 새 나눔과 말씀은 기존 글·날짜별 태그를 유지한다. 회원이 허용한 화면 표시용 메시지는 `Urgency: high`로 전달을 요청하며, 기기 표시 시각을 보장하지는 않는다.
- 404/410처럼 만료된 구독은 비활성화하고 원문은 유지한다.
- 일시적 제공사 실패는 제한된 재시도로 복구한다. 최대 5회 후 멈추며, 제공사 수락 여부가 불명확한 발송은 자동 재전송하지 않는다. 잠금·해제 등으로 자격을 잃으면 대기 작업을 취소 상태로 남긴다.
- iPhone·iPad는 지원되는 iOS/iPadOS의 홈 화면 웹 앱에서 실행하고 기기에서 알림을 허용해야 한다. 지원하지 않거나 권한이 차단된 기기에는 연결 안내만 표시한다.

## 안전한 확인

기존 회원 글·습관·자료를 테스트용으로 수정하지 않는다. 데이터베이스 검증은 합성 데이터가 든 임시 PGlite에서 수행한다. 운영에서는 예약 작업의 존재, 고정 오류 코드, 상태·수신 건수와 본인이 요청한 테스트 알림만 확인한다. 원시 구독·암호화 키·제공사 오류 본문·JWT·실제 회원 본문을 진단 로그에 담지 않는다.

제공사 수락(`sent`, `last_sent_at`)과 기기 알림 표시를 구분한다. 연결 화면의 **최근 서버 발송**은 제공사 수락 시각이며 수신 확인이 아니다. **기기 알림 표시 확인**은 현재 연결된 동일 원점·루트 서비스 워커의 `showNotification`만 호출하며 서버 테스트 작업을 만들지 않는다. 사용자에게 두 검사 결과를 각각 확인하여, 로컬 표시/기기 설정과 서버→푸시 서비스→기기 전달 중 어느 구간인지 좁힌다. 로컬 표시 API가 성공해도 실제 배너나 소리가 났다고 단정하지 않는다.
