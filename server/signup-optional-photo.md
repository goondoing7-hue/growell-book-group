# 프로필 사진 선택 가입 후속 변경

2026-09-29 요청을 위한 변경 파일이다. 운영 적용 완료를 뜻하지 않는다. 이전 사진 필수 계약인 `member-approval.sql`, `signup-notifications.sql`은 이력으로 보존하고, **그 두 파일 뒤에 `signup-optional-photo.sql`을 적용**한다. 이전 기본 마이그레이션을 재적용하면 사진 필수 함수가 복원되므로 후속 변경도 다시 적용해야 한다.

- `signup.ts`에서 사진 누락·`null`·빈 문자열은 사진 미선택으로 처리한다. `avatars` 업로드를 호출하지 않고 `avatar_url=null`로 가입을 신청한다.
- 사진을 첨부하면 기존 크기·형식·시그니처 검사와 업로드 성공 확인을 그대로 수행한다. 잘못된 첨부를 사진 없음으로 조용히 무시하지 않는다.
- 별명·아이디·비밀번호·salt·비밀번호 힌트는 기존 서버 검증을 유지한다. 힌트 질문 ID와 답변을 합친 문자열은 기존 `pwHint` / `pw_hint`에 한 값으로 저장·비교한다. 회원가입과 비밀번호 찾기 화면에서 동일한 직렬화를 사용해야 한다. 기존 회원의 자유 입력 힌트를 변환하거나 덮어쓰지 않는다.
- 후속 SQL은 가입 트리거, 직접 INSERT 정책, 관리자 승인 RPC, 가입 확정 RPC의 **사진 필수 조건만 제거**한다. 새 계정의 `pending`·`is_admin=false`, 승인 전 접근 제한, 관리자만 승인·거절, 본인 승인 금지, 동시 처리 충돌 방지는 그대로다.
- 힌트 저장과 관리자 알림 대기열 등록은 여전히 한 트랜잭션이다. 필수 힌트 저장 실패를 가입 성공으로 반환하지 않는다. 실패 정리는 이번 요청에서 생성이 확인된 계정만 대상으로 하며 사진을 선택하지 않았으면 Storage 정리도 호출하지 않는다.
- 기존 회원 프로필, 사진, 승인 상태, 비밀번호, 힌트, 암호화 키, 기록과 기존 알림 작업은 변경하지 않는다. 숨겨 둔 소셜 신규가입 경로도 사진 조건은 더 이상 요구하지 않지만 신규 프로필은 계속 승인 대기이며, 제공자·기존 계정 연결 검사는 유지된다.

배포 전에는 `signup-optional-photo.sql`의 마지막 `COMMIT`을 빼고 `signup-optional-photo-verification.sql`을 붙여 실행한다. 임시 사용자로 사진 없는 가입·힌트·알림 대기열·승인·승인 전 차단을 검사한 뒤 마지막 `ROLLBACK`으로 모두 복원한다. 검증 중 메일 발송 함수를 호출하지 않는다. 확인 후 후속 SQL을 적용하고 새 `signup.ts`, 프런트엔드 순서로 배포한다.

로컬에서는 `tests/signup-edge.test.cjs`가 실제 Edge 핸들러를 모의 저장소로 실행한다. 이 검사는 운영 데이터베이스 RLS 검증을 대신하지 않는다.
