# 가입 승인·활동지 잠금 배포 계약

이 문서는 `member-approval.sql`과 `worksheet-locks.sql`의 서버 계약이다. 파일 생성이나 프런트엔드 배포만으로 운영 데이터베이스에 적용되지는 않는다. 운영 적용 및 실제 역할 검증 결과는 별도로 확인한다.

## 가입 및 기존 회원

- 최초 마이그레이션에서 이미 존재하는 프로필만 `approval_status='approved'`로 보존한다. 기존 회원의 비밀번호, ID, 관리자 여부, 암호화 키, 기록은 수정하지 않는다. 기존 승인의 날짜나 승인자는 추정해서 채우지 않는다.
- 이후 새 프로필은 서버가 넘긴 값과 관계없이 일반 권한(`is_admin=false`)의 `pending`으로 생성된다. 관리자 코드로 생성한 계정도 자동 승인되지 않는다. 기존 `grant-admin` 서비스 역할 함수가 승인 전 관리자 승격을 시도해도 트리거에서 거절한다.
- 새 프로필에는 공백이 아닌 `avatar_url`이 필요하다. 실제 사진의 형식·크기·업로드 성공 여부는 `signup` Edge Function에서 별도로 검증한다. Edge는 사진 업로드가 끝난 뒤 프로필을 등록해야 한다.
- `signup.ts`는 입력 형식·개인키 salt·사진을 가입 생성 전에 확인한다. 필수 비밀번호 힌트 저장 실패를 가입 성공으로 반환하지 않는다. 사진·프로필·힌트 저장 실패나 네트워크 예외에서는 **이번 요청에서 생성이 확인된 Auth ID**의 자원만 정리하고, 정리 실패도 응답에 표시한다. 기존 계정의 ID를 검색해 정리하지 않는다.
- 가입 성공은 **가입 신청 접수**를 뜻한다. 프런트엔드는 자동 로그인으로 회원 공간을 열지 않고 관리자 승인 대기를 안내한다. 로그인/자동 복원 시 승인 상태를 다시 조회한다.
- 승인 대기·거절 계정은 본인 프로필 상태만 조회할 수 있다. 다른 회원 자료, 개인 기록, 습관을 포함한 회원 테이블의 조회·수정·추가는 RLS로 차단한다. 일반 회원은 대기·거절 프로필을 조회하지 못하고 승인된 관리자만 가입 신청 목록을 읽는다.
- `growell_review_member(p_profile_id, p_decision)`은 승인된 관리자만 호출할 수 있다. `p_decision`은 `approved` 또는 `rejected`다. 승인 시 사진을 재확인하고 `approved_at`, `approved_by`를 서버에서 저장한다. 동일 결정 재시도는 같은 결과를 반환하며, 다른 관리자가 먼저 처리한 요청의 반대 결정은 충돌로 거절한다.
- 상태 필드 직접 수정은 트리거로 제한한다. 기존 `is_current_user_admin()`도 승인된 관리자만 참으로 판정한다. 서비스 역할의 기존 `grant-admin`이 `is_admin`만 수정해도 승인 전 승격은 트리거로 거절한다. 신규 승인 대기 계정은 `is_admin=false`이므로 기존 `delete-account`의 관리자 분기에 들어갈 수 없다. 다른 서비스 역할 기능이 승인 조건을 우회하지 않는지도 별도로 검토한다.
- 현재 숨긴 소셜 신규가입 RPC는 사진 없이 프로필을 생성하므로 새 사진 필수 트리거 아래에서는 등록되지 않는다. 소셜 UI를 다시 켜기 전에는 프로필 사진과 승인 대기 계약을 소셜 등록에도 추가해야 한다. 기존 승인된 소셜 회원/암호화 키 보관함은 그대로 유지된다.

## 활동지

- 책 전체 공개 여부와 별도로 `growell_worksheet_locks`에 책별 잠금을 저장한다. 설정이 없는 책은 잠김이다. 이전의 영구 관리자 전용 정책을 책별 잠금 정책으로 교체한다.
- 승인된 관리자는 잠금과 관계없이 활동지를 열 수 있다. 승인된 일반 회원은 관리자가 연 책의 활동지만 읽고 본인 답변을 작성할 수 있다. 기존 소유자 수정 제한은 유지한다.
- `growell_get_worksheet_locks()`는 네 권의 `{book_id, locked, revision}`을 반환한다. 조회 실패 시 화면은 잠긴 상태로 유지해야 한다.
- `growell_set_worksheet_lock(p_book_id, p_locked, p_expected_revision)`은 관리자 전용이다. 처음 설정할 때 `revision=0`을 넘기며 이후 마지막 조회 버전을 사용한다. 충돌은 재조회 후 다시 선택하도록 안내한다.
- 활동지를 다시 잠가도 기존 답변은 삭제하지 않는다. 잠긴 뒤 기존 화면에서 보내는 저장 요청도 데이터베이스에서 거절한다.

## 배포 전 확인

1. 실서버 `signup` 소스에서 필수 사진 검증, 업로드 실패 처리, 실패 시 새 Auth 사용자 정리, `is_admin:false` 등록을 확인한다. 기존 `grant-admin` 승격은 새 트리거가 차단하고 `delete-account`의 관리자 조건에는 신규 대기 계정이 해당하지 않는 것을 함께 확인한다.
2. 기존 함수와 RLS 정의를 비교한다. `member-approval.sql`의 마지막 `COMMIT`을 빼고 `member-approval-verification.sql`을 붙여 임시 사용자 역할 검증을 실행한다. 최종 `ROLLBACK`으로 스키마와 검증 데이터를 모두 복원한다.
3. 검증을 통과한 승인 마이그레이션을 적용한다. 이어서 `worksheet-locks.sql`과 검증 파일도 같은 방식으로 먼저 롤백 검증 후 적용한다.
4. SECURITY DEFINER 질문 조회·수정·댓글 함수는 `growell_is_active_member()` / `growell_is_approved_admin()`을 사용해야 한다. 그 외 기존 Edge Function·별도 RPC는 테이블 RLS를 우회할 수 있으므로 각각 승인 조건을 검토한다.
5. 프런트엔드에서 기존 회원 로그인, 새 가입 신청·승인 후 로그인, 일반 회원의 승인 메뉴 차단, 잠긴/열린 활동지, 다시 잠근 뒤 저장 거절을 임시 데이터로 검증한다.

Storage의 기존 공개 이미지 URL은 이 변경으로 비공개가 되지 않는다. `avatars`, `post-photos`에 대한 인증 사용자의 새 업로드·수정·삭제는 승인 여부를 추가 확인하되, 기존 소유자 정책을 유지한다.
